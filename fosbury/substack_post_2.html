The "Ghost Demand" Problem

Historically, if you wanted to build a data center, you could apply to connect to the grid for a massive allocation (say, 100 megawatts) and slowly ramp up your usage over a decade. Crucially, you only paid the utility for the power you actually drew. It was essentially a free, zero-risk option on future growth.

This loophole triggered an absolute gold rush. Developers flooded utility queues with speculative requests, creating a mountain of "ghost demand." Utilities were forced to map out billions of dollars in transmission line upgrades to support capacity that might never actually be used.

But public utility commissions have a legal mandate to protect ordinary residential homeowners from footing the bill for "stranded assets" if these tech projects fail. To fix this, regulators are quietly rolling out a highly restrictive, un-fakeable economic mechanism: The Take-or-Pay Tariff.

My data engine mapped three major shifts in the PJM footprint that are about to rewrite the economics of the entire sector:

1. Virginia (Dominion Energy's GS-5)

In Northern Virginia — the data center capital of the world — the State Corporation Commission officially approved Dominion's new GS-5 rate class, going into effect on January 1, 2027. (Based on regulatory filings monitored by Project Fosbury — specific contract terms subject to final tariff language.)

  • The Rule: Any large electrical load over 25 MW must sign a binding 14-year contract backed by heavy upfront collateral.
  • The Catch: They must pay a monthly minimum of 85% of their contracted capacity — even if their data center sits completely empty.

2. Pennsylvania (The PUC Model Tariff)

In May 2026, the Pennsylvania Public Utility Commission finalized its Model Large Load Tariff, which local utilities like PPL are actively adopting. (Based on PA PUC docket filings monitored by Project Fosbury.)

  • The Rule: It institutes an 80% take-or-pay floor and a minimum contract term of at least five years.
  • The Catch: It implements a strict "but-for" cost-causation standard. If a local substation upgrade is required but for the data center connecting, the developer must pay 100% of those multi-million-dollar infrastructure costs upfront.

3. Ohio (AEP's Take-or-Pay Tariff)

AEP Ohio pioneered this trend, establishing an 85% take-or-pay threshold and forcing non-investment-grade developers to put up massive credit guarantees.

What Happens When Speculators Hold the Bag?

When state utility commissions force developers to back up their speculative power requests with hard, unrecoverable capital and 14-year liabilities, the "paper pipelines" evaporate.

In Ohio, when forced to face AEP's strict collateral requirements, massive chunks of speculative capacity are quietly being withdrawn. Here is the language directly from AEP's formal filing:

"The Columbus data center interconnection cluster has withdrawn 24,300 MW of uncommitted capacity requests following implementation of the take-or-pay tariff. Expected commercial operation dates have been extended by an average of 14 months across the affected queue positions. AEP projects that confirmed contracted load has declined from 30,000 MW to 5,700 MW of bankable demand."

— American Electric Power, Ohio PUC System Impact Study Update

In Virginia, the pending 2027 launch of Dominion's GS-5 tariff is forcing a rapid, silent sorting mechanism across the entire state. If a developer does not have a trillion-dollar balance sheet or a signed lease with a Tier-1 hyperscaler (like Microsoft, AWS, or Google) who can guarantee immediate, high-volume power usage, they simply cannot afford to stay in the queue.

Inside the Tech Stack: How Project Fosbury Works

Instead of trying to scrape raw HTML charts from PJM's front page (which they explicitly block to limit heavy web-scraping), I built a modular data pipeline split into abstract layers: data extractors, automated PDF parsers, a normalization layer, and local storage.

The pipeline uses Python to query the EIA Open Data API for real-time electricity demand data by balancing authority, alongside custom scrapers that constantly ingest messy municipal PDF agendas and state-level regulatory dockets across VA SCC, PA PUC, and Ohio PUCO. For larger-scale grid studies, the architecture also supports the PJM Data Miner 2 API when a subscription key is available.

Everything is stored in a local SQLite file (fosbury.db) using Python's built-in sqlite3 library — no external ORM needed. Every scraped event is parsed into a standardized Pydantic data model called GridEvent:

# Core data model — every scraped event normalizes into this shape
class GridEvent(BaseModel):
    event_id: str               # SHA-256 hash of source_url + text excerpt
    iso_region: str             # e.g. "PJM"
    state_jurisdiction: str     # e.g. "VA", "OH", "PA", "FEDERAL"
    entity_target: str          # e.g. "American Electric Power"
    data_type: str              # QUEUE_MILESTONE, REGULATORY_PROTEST, etc.
    raw_text_blob: str          # cleaned text excerpt up to 2000 chars
    metric_delta: int = 0       # quantified delay in calendar days
    keywords_matched: list[str] = []
    source_url: str = ""

By tracking the unique event_id, metric_delta, and state_jurisdiction across thousands of dockets, the engine flags exactly when a project's "washout risk" spikes.

Here is the core function that actually reads a regulatory PDF and decides whether it contains a signal worth flagging:

# Core signal detection — scans a downloaded regulatory PDF
def scan_pdf(pdf_bytes: bytes) -> PdfScanResult:
    """
    Extracts text from a regulatory PDF and checks it against
    the keyword list. Two or more matches triggers a flag.
    """
    with pdfplumber.open(BytesIO(pdf_bytes)) as pdf:
        text = "\n".join(page.extract_text() or "" for page in pdf.pages)

    matched = [kw for kw in ALL_KEYWORDS if kw.lower() in text.lower()]
    metric_delta = _extract_delay_days(text)  # regex pulls month/day figures

    return PdfScanResult(
        keywords_matched=matched,
        metric_delta=metric_delta,
        full_text=text,
        has_signal=len(matched) >= 2,
    )
